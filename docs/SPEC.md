# YAMATO FLEET 2199 — Demo Spec & Interface Contract

> Working title: **YAMATO FLEET 2199**. A browser (Three.js, no build step) space
> capital-ship combat demo inspired by *Space Battleship Yamato 2199 / 2202*.
> Original fan work — no copyrighted assets are used; all models/audio are
> generated by our own tooling.

This file is the **single source of truth for interfaces**. Every teammate must
read it before writing code. Do not change an interface without telling the Lead.

---

## 1. Product scope (demo v0.1)

A single playable scenario, ~5 minutes:

| Element | Decision |
|---|---|
| View | Third-person chase camera behind the player's ship, free-look |
| Player ship | Earth Federation **Yamato (BBY-01)**, Yamato-class space battleship |
| Player weapons | Shock cannon (main/secondary turrets), torpedo salvo, **Wave Motion Gun** (charge + fire) |
| Enemies | Garmillas Empire fleet (waves 1–2), Bolar Federation fleet (wave 3) |
| Damage model | Shield → Armor → Hull, plus **subsystem damage** (wave motion gun, engine, turrets) |
| Fleet AI | Formation keeping, broadside engagement, focus fire, wave-motion-gun telegraph |
| HUD | Reticle, hull/armor/shield, WM-gun charge meter, target panel, radar, kill feed, wave banner |
| Audio | 100% procedural WebAudio synthesis (no audio files shipped) |
| Win / lose | Survive all 3 waves = victory; hull 0 = defeat |

**Out of scope for v0.1** (do not build): multiplayer, campaign, ship customization,
save games, mobile touch controls, real physics collision mesh.

## 2. Runtime & build

- **No bundler.** Native ES modules + an HTML **import map**.
- `three` → `./vendor/three/three.module.js` (r160, MIT, vendored).
- `three/addons/` → `./vendor/three/` (OrbitControls, OBJLoader, MTLLoader, EffectComposer, RenderPass, UnrealBloomPass, ShaderPass, CopyShader, LuminosityHighPassShader, OutputPass).
- Served by `node tools/serve.mjs` (static server, default port **8177**).
- Target: current Chrome/Safari. WebGL2 assumed.
- Pure-logic modules must be importable by Node (`node:test`) **without** touching `three` or `window`. Keep DOM/three access out of those files, or guard it.

## 4. Coordinate & unit conventions (MUST match)

- Units: **1 world unit = 1 metre**, but ships are placed with a game scale
  factor `SHIP_SCALE = 1.0` (real sizes are large; keep them, and keep camera
  distances large too — this makes the "capital ship" feel correct).
- **Ship local space**: bow points toward **−Z**, up is **+Y**, origin at the
  ship's centre (mid-length, centreline, mid-height).
- World space: right-handed, Y-up, no gravity, no drag unless a module applies it.
- Rotations: **quaternions** everywhere. Never accumulate Euler angles across frames.
- Angles in radians.

## 5. Asset contract (`assets/models/`)

`assets/models/manifest.json` is generated by `tools/gen_models.py` and read by
`src/core/assets.js`. **Schema (frozen):**

```jsonc
{
  "schema": "yamato-fleet/models@1",
  "units": "meters",
  "axis": { "forward": "-Z", "up": "+Y" },
  "models": [
    {
      "id": "yamato",                    // stable key used by src code
      "displayName": "Yamato (BBY-01)",
      "displayNameJa": "ヤマト",
      "faction": "uncf",                 // uncf | garmillas | bolar
      "shipClass": "Yamato-class",
      "role": "battleship",              // battleship|cruiser|destroyer|carrier|flagship
      "obj": "yamato.obj",
      "mtl": "yamato.mtl",
      "lengthM": 333,
      "beamM": 48,
      "triangles": 4210,
      "groups": ["hull", "superstructure", "bridge", "wave_motion_gun",
                 "engine_nozzle", "turret_main", "turret_secondary"],
      "hardpoints": [
        { "name": "wave_motion_gun", "kind": "wmgun",  "pos": [0, 2.0, -150], "dir": [0, 0, -1] },
        { "name": "turret_main_1",   "kind": "turret", "pos": [0, 12, -70],  "dir": [0, 0, -1] },
        { "name": "engine_1",        "kind": "thruster","pos": [-14, 0, 150],"dir": [0, 0, 1] }
      ],
      "materials": ["hull_grey", "hull_red", "deck_dark", "glass_blue",
                    "engine_glow", "gun_metal", "accent_gold"]
    }
  ]
}
```

Hardpoint `pos`/`dir` are in **ship local space** (metres), `dir` normalised.

### OBJ/MTL rules for the generator

1. **One OBJ + one MTL per ship**, ASCII, no textures (vertex colours are not
   used; flat PBR materials only).
2. Faces must be triangles or quads; no n-gons.
3. Use `g <groupname>` for the part groups listed in `groups` above (subset OK).
   Group names are a **stable API** — the renderer recolours/animates by group.

   **A group family is a weapon SLOT, not a calibre (binding).** `turret_main`
   means "this hull's primary battery" — 48 cm on Yamato, 40.6 cm on Andromeda.
   `turret_secondary` means "this hull's secondary battery", and on a hull whose
   canon fit has no gun of that class, the slot is filled by whatever her
   mid-calibre armament actually is (Andromeda's quad anti-ship grenade
   projectors, for instance). Do **not** invent armament a ship never carried in
   order to satisfy a family name, and do not drop the family: the renderer reads
   `CONFIG.weapons.<id>.mountPrefix` to find where a weapon fires from, so a
   missing family is a silent gameplay hole disguised as fidelity.

   **Indexed turret groups (added for turret traverse).** A weapon mount that the
   renderer must be able to rotate on its own gets an INDEXED group name:
   `turret_main_1..N`, `turret_secondary_1..N`, `ciws_1..N`. The index must match
   the corresponding hardpoint name in `manifest.json` (`turret_main_1` group ↔
   `turret_main_1` hardpoint).

   **Pivot contract for indexed groups (binding).** The geometry of an indexed
   turret group is authored **centred on its own pivot**: the origin is on the
   turret's vertical rotation axis, at the deck line where the barbette meets the
   hull. The renderer positions the group at the hardpoint's `pos` and rotates it
   about its local +Y to aim. So a turret authored this way sits correctly with
   `mesh.position = hardpoint.pos` and `mesh.rotation.y = 0` meaning "trained
   fore-and-aft". Do NOT bake the turret's world position into its vertices.

   A model may also ship a single merged `turret_main` group (no index) — the
   renderer then draws it as-is and simply cannot traverse it. Indexed groups are
   strongly preferred.
4. Normals: write `vn` per vertex, or omit and let three.js compute them.
   Prefer writing them. Normals on an indexed turret group must be in the
   turret's own local frame (consistent with the pivot contract in rule 3).
5. Material names must come from this fixed palette:
   `hull_grey`, `hull_red`, `deck_dark`, `glass_blue`, `engine_glow`,
   `gun_metal`, `accent_gold`, `hull_green`, `hull_olive`, `hull_white`,
   `hull_black`, `bolar_blue`.
6. Keep every ship under **12 000 triangles** (demo budget).
7. Ship must fit `lengthM` along Z (bow at −lengthM/2, stern at +lengthM/2) and
   be roughly centred in X.

### 6.2 `src/core/config.js` (Lead)

Exports `CONFIG` (tunables: speeds, damage, ranges, camera, bloom, wave sizes).
**All balance numbers live here.** Other modules must not hardcode balance.

### 6.3 `src/entities/ship.js` (Lead)

```js
export class Ship {
  constructor({ model, def, faction, isPlayer, spawn })   // model = ShipModel
  // state
  position: THREE.Vector3; quaternion: THREE.Quaternion; velocity: THREE.Vector3
  throttle: number;             // -1..1
  hull, hullMax, armor, armorMax, shield, shieldMax: number
  alive: boolean; faction: string; callsign: string
  subsystems: Record<string, {hp:number, max:number, disabled:boolean}>
  target: Ship|null
  // api
  update(dt, world): void
  applyDamage(amount, {type, from, hitPoint}): DamageResult
  getHardpointWorld(name): {pos:THREE.Vector3, dir:THREE.Vector3}
  fireWeapon(name, world): boolean
  dispose(): void
}
// DamageResult = { absorbed, shieldHit, armorHit, hullHit, killed, subsystemHit }
```

`world` (the simulation context) is provided by `src/main.js`:

```js
// world = {
//   scene, dt, time,
//   ships: Ship[], projectiles: Projectile[], effects: Effects,
//   spawnProjectile(p), spawnEffect(e), audio, events: EventBus,
//   player: Ship, rng
// }
```

### 6.4 `src/weapons/weapons.js` (Lead)

```js
export const WEAPONS = { shock_cannon: {...}, secondary: {...}, torpedo: {...},
```

### 6.5 `src/ui/hud.js` (engine-dev)

```js
export class Hud {
  constructor(rootEl, world)
  update(dt, world): void       // called every frame after simulation

```
HUD is **DOM/CSS** (fast, crisp text), not canvas, except the radar.
`index.html` provides `<div id="hud"></div>`; Hud builds its own subtree inside it.

### 6.7 `src/ai/fleetai.js` (engine-dev)

```js
export class FleetAI {
  constructor({ faction, ships, world, doctrine })   // doctrine: 'garmillas'|'bolar'|'uncf'
```

Wave definitions live in `CONFIG.waves` (Lead). FleetAI must not hardcode ships.

### 6.8 `src/core/audio.js` (engine-dev)

```js
export class AudioEngine {
  constructor(); resume(): Promise<void>; setMasterVolume(v): void
  play(name, opts): void        // 'shock_cannon'|'wmgun_charge'|'wmgun_fire'|'explosion_small'
                                // 'explosion_big'|'torpedo'|'engine_loop'|'alarm'|'ui_click'|'shield_hit'
  startEngineLoop(ship): void; stopEngineLoop(): void
  update(dt, world): void

```
Synthesis only: oscillators, noise buffers, filters, envelopes. Must not fetch files.

### 6.9 `src/core/input.js` (Lead)

```js
export class Input {
  constructor(targetEl)
  keys: Set<string>; mouse: {dx,dy,left,right,wheel}
  isDown(code): boolean; consumePressed(code): boolean   // edge-triggered
}
```
Bindings (default, also in `CONFIG.keys`): `KeyW/KeyS` throttle, `KeyA/KeyD` yaw,
`KeyQ/KeyE` roll, `KeyR` wave motion gun (hold to charge, release to fire),
`Space` shock cannon, `KeyF` torpedo, `ShiftLeft` boost, `Tab` cycle target,
`KeyC` camera mode, `KeyP` pause.

## 7. Testing & verification

- `tests/*.test.mjs` run with `node --test tests/`. Pure logic only.
- Verifier owns tests + `evidence/` (screenshots, console logs, JSON reports).
- Definition of done for the demo:
  1. `node tools/serve.mjs` starts; `http://127.0.0.1:8177/` returns 200.
  2. Page loads with **zero console errors** and renders the Yamato.
  3. Player can move, fire shock cannons, fire torpedoes, charge+fire the WM gun.
  4. Enemies spawn, manoeuvre, shoot back, and can be destroyed.
  5. HUD shows hull/shield/charge/target/radar and updates live.
  6. Wave 1→2→3 progression works; victory and defeat states reachable.
  7. `node --test tests/` passes.
  8. Screenshot evidence in `evidence/` for: title/HUD, combat, WM gun firing,
     explosion, victory screen.
