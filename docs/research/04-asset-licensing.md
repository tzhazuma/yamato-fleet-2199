## 1. RECOMMENDED ASSET POLICY

### 1.1 The one-liner (for `README.md` / SPEC §8)

> **YAMATO FLEET 2199 ships no third-party art or audio.** Every mesh is
> generated by our own Python tool (`tools/gen_models.py`) from parametric
> primitives, and every sound is synthesised at runtime by `src/core/audio.js`
> from oscillators and noise buffers. No model, texture, sprite, sound file,
> font, or motion data from any third party — free, open, or otherwise — is
> included in this repository. Research informed shapes, palettes and numbers
> only.

### 1.2 The five rules

| # | Rule | Why |
|---|---|---|
| **R1** | **No third-party art is vendored, downloaded, or shipped.** Not even CC0. | CC0 removes *copyright* friction but not *provenance* friction. §4 shows several nominally-open sources where the uploader did not have the rights they granted. A "no third-party art" rule is the only policy that needs no per-asset audit, and it is already SPEC §8. |
| **R2** | All geometry comes from `tools/gen_models.py`. | It is the only way to guarantee R1 *and* the frozen SPEC §5 manifest schema (groups, hardpoints, triangle budget, material palette). |
| **R3** | All audio is synthesised at runtime. | SPEC §6.8 already mandates it. Also avoids the single most litigated asset category in fan works (see §6). |
| **R4** | If a third-party asset is *ever* added, it must be CC0 **or** CC-BY, and it must land with an entry in `CREDITS.md` plus the upstream URL and the license text. | §3.4 gives the exact procedure. |
| **R5** | No model, texture, sprite, or sound derived from *Space Battleship Yamato* media — ever. No rips, no traces, no rotoscoping, no sampled audio. | §6. This is the rule that actually matters legally. |

### 1.3 Why not just use CC0 assets?

Tempting, and it would save asset-forge a lot of work. Rejected because:

1. **It breaks SPEC §5.** The manifest schema needs *named part groups*
   (`hull`, `bridge`, `wave_motion_gun`, `turret_main`, …) and *hardpoints* with
   local-space `pos`/`dir`. No off-the-shelf model has those. asset-forge would
   have to open and re-cut every mesh anyway — at which point generating from
   scratch is cheaper.
2. **Triangle budget.** SPEC §5 caps every ship at 12 000 triangles. A single
   downloaded "sci-fi spaceship" is routinely 50 k–500 k. Decimating to budget
   is more work than modelling.
3. **Style coherence.** Eight ships from six different CC0 authors look like
   eight ships from six different CC0 authors. A generated fleet shares one
   silhouette language, which is the whole point of a *tribute*.
4. **The Yamato is a specific, recognisable design.** §6.2: we need an
   *original* design that evokes the silhouette without copying it. A CC0 asset
   is either wrong or it is a copy.

### 1.4 What would change if a CC-BY asset were ever added

Not currently planned; documented so the rule is actionable rather than a vibe.

**Required, in this order:**

1. **`CREDITS.md` at the repo root** (new file) with, per asset:
   * asset title as published
   * creator name (or pseudonym)
   * source URL (the *specific* asset page, not the site root)
   * license identifier + version (`CC-BY-4.0`) and a link to the deed
   * the exact changes made ("decimated 240 k → 9 k tris; re-cut into groups;
   re-materialed to `hull_grey`")
   * the date retrieved
2. **The full license text** in `LICENSES/CC-BY-4.0.txt`. CC-BY requires a link
   to the license, and shipping the text is the safe form.
3. **A visible in-product credit.** CC-BY-4.0 §3(a)(2) requires attribution
   "in the manner specified"; for a browser demo the defensible places are a
   credits line on the title overlay *and* a `CREDITS.md` link. Attribution only
   in a source file is **not** sufficient for a distributed work.
4. **A "no endorsement" line.** CC-BY-4.0 §3(a)(1)(B) forbids implying the
   licensor endorses the use. Add: *"This project is not affiliated with, or
   endorsed by, the creators listed above."*
5. **The asset's own license file** copied next to the asset in `assets/`.
6. **A note in the manifest entry.** SPEC §5's schema is frozen, so the extra
   fields must go in a *sibling* `assets/models/CREDITS.json` rather than into
   `manifest.json`. **Do not** extend the frozen schema for this.

**Non-negotiables for a CC-BY asset:** it must be **CC-BY-4.0** (not 3.0, not
unversioned), the creator must be named, and if it is **CC-BY-SA** it must be
rejected outright — ShareAlike on a mesh is a viral obligation this demo should
not take on.

**Licenses we would reject even if the asset were free:** `GPL`/`AGPL` art
(copyleft spreads to the whole demo's distribution terms), `CC-BY-NC` (blocks any
future commercial use), `CC-BY-ND` (blocks the decimation/re-materialing we would
need), and anything with **no license stated** — which, per CC's own guidance, is
all-rights-reserved by default.

### 1.5 Licensing caveats for our own toolchain

| Component | License | Effect on us |
|---|---|---|
| `three` r160 (vendored, SPEC §2) | MIT | Ship the MIT notice in `vendor/three/LICENSE`. Already required. |
| Python `trimesh` | MIT | Safe dependency for a generator we ship. |
| Python `numpy` | BSD-3-Clause | Safe. |
| **Blender + `bpy`** | **GPL-2.0-or-later** | **The one real trap.** See §5.2. |

## 3. Our policy, confirmed

### 3.1 Geometry — 100 % generated

`tools/gen_models.py` (asset-forge) emits, per SPEC §5:

* one ASCII **OBJ** + one **MTL** per ship
* `g <groupname>` for each named part group (`hull`, `superstructure`, `bridge`,
  `wave_motion_gun`, `engine_nozzle`, `turret_main`, `turret_secondary`)
* triangles/quads only, `vn` normals written
* ≤ 12 000 triangles per ship
* materials drawn only from the frozen 12-name palette
* ship centred on X, bow at `−lengthM/2`, stern at `+lengthM/2`
* a generated `assets/models/manifest.json` conforming to
  `yamato-fleet/models@1`

`tools/validate_models.py` (asset-forge) should assert every one of those
constraints so the verifier can trust the manifest.

**Provenance statement for the README:** *all ship geometry is procedurally
generated from parametric primitives; no scanned, downloaded, or third-party
mesh data is present in this repository.*

### 3.2 Audio — 100 % synthesised at runtime

SPEC §6.8 already fixes this: `AudioEngine` builds every sound from
oscillators, noise buffers, filters and envelopes, and "must not fetch files".
No `.mp3`, `.ogg`, `.wav`, or `.m4a` is shipped, and **no audio sampled from the
anime is used** — that is the highest-risk asset category in any fan project
(§6.3).

### 3.3 Sprites, fonts, UI

* **Radar, reticle, HUD chrome:** drawn with Canvas2D / DOM+CSS at runtime
  (SPEC §6.5, §6.6). No image files.
* **Fonts:** system font stack only (`ui-monospace, SFMono-Regular, Menlo,
  monospace` etc.). Do **not** ship a webfont — that would be a third-party
  asset and a licensing surface for zero benefit.
* **Textures:** none. SPEC §5 rule 1 forbids them; flat PBR materials only.

### 3.4 The CC-BY addendum procedure (dormant)

If R4 is ever invoked, the complete checklist is §1.4. The trigger to revisit
this file is: *any* new file appearing under `assets/` that was not written by
`tools/gen_models.py`.

## 4. Risk notes on "free" asset repositories

Not legal advice; engineering risk assessment.

| Risk | Reality | Mitigation |
|---|---|---|
| **Uploader had no rights** | The dominant failure mode. A user uploads a ripped game model and tags it CC0; the tag is a lie and the platform disclaims verification (Poly Pizza's ToS is explicit that it does not warrant uploader rights). | R1 — use nothing. |
| **License is mutable** | Poly Pizza binds you to "the license that applies **at the time of download**". A model can be re-licensed or deleted later; your evidence disappears. | Archive the asset page (screenshot + WARC/PDF) and record the retrieval date, if you ever use one. |
| **"CC0" applied to a derivative** | CC0 is only valid if the affirmer had the rights to waive. A CC0 tag on a derivative of a copyrighted ship design is void. | R5 — refuse anything resembling the licensed IP. |
| **Copyleft creep** | GPL/CC-BY-SA art can be argued to infect the distribution terms of the whole work. | Reject GPL, AGPL, CC-BY-SA, and OGA-BY. |
| **Trademark ≠ copyright** | CC0 explicitly does not affect patent or trademark rights, and CC's own deed notes publicity/privacy rights are untouched. A CC0 *model* of a trademarked ship is still a trademark problem. | R5 again. This is why CC0 is not a free pass. |
| **AI-training clauses** | Poly Pizza's ToS forbids using site data for ML/AI training. Kenney's does not. These clauses are new, inconsistent, and easy to trip accidentally with a scraper. | Never scrape. This document was produced by reading pages in a browser, not by bulk download. |

## 5. Tooling survey for self-made assets

### 5.1 The options

| Option | Language / license | Writes | Strengths | Weaknesses |
|---|---|---|---|---|
| **A. Blender `bpy` scripting** | Python, Blender is **GPL-2.0-or-later** ([license page](https://www.blender.org/about/license/)) | `.blend`, OBJ, MTL, glTF, everything | Full CSG/boolean/bevel/subdiv toolkit; best-in-class mesh ops; `bpy.ops.wm.obj_export` writes OBJ+MTL directly | **GPL reach (see §5.2)**; heavyweight dependency; needs a Blender install in CI; `bpy` ops are context-sensitive and awkward to run headless |
| **B. Python `trimesh` + `numpy`** | MIT / BSD-3-Clause ([trimesh docs](https://trimesh.org/), [`export_obj`](https://trimesh.org/trimesh.exchange.obj.html)) | OBJ + MTL, STL, PLY, glTF | `pip install trimesh` (numpy is the only hard dep); pure-Python; primitives (`Box`, `Cylinder`, `Sphere`, `Extrusion`), booleans via Manifold3D, `export_obj(..., mtl_name=...)` writes OBJ+MTL in one call; trivially scriptable in CI; **permissive license** | No interactive modelling; you must think in code; booleans need the `manifold3d` soft-dep |
| **C. three.js procedural geometry** | MIT | In-memory `BufferGeometry` only | Zero extra toolchain; ships with the app; instant iteration | **Violates SPEC §5** — the contract requires OBJ+MTL files plus a generated `manifest.json`. Also bakes generation into load time and makes the tri budget unverifiable by a Python validator |
| **D. SVG / Canvas sprite generation** | MIT (three.js) / stdlib | 2D images | Perfect for the **radar**, reticle, HUD icons and explosion sprites | Cannot produce a 3D capital ship. Useful *alongside* A/B, not instead of |
| **E. Hand-modelling in Blender's UI** | GPL app | `.blend` → OBJ | Best artistic control | Not reproducible, not reviewable in a diff, not automatable, and the Lead/verifier cannot regenerate it |

### 5.2 The Blender GPL trap — read this before choosing A

Blender's own license page states two things that must be read together:

> "Blender's Python API is an integral part of the software… The GNU GPL
> license therefore requires that such scripts (if published) are being shared
> under a GPL compliant license."

> "What you create with Blender is your sole property. All your artwork –
> images or movie files – including the .blend files and other data files
> Blender can write, is free for you to use as you like."

**What this means concretely:**

* The **models** you generate with Blender are yours, no strings. GPL does not
  reach the OBJ output.
* A **published script that imports `bpy`** must itself be GPL-compatible.
  `tools/gen_models.py` is published (it is in the repo and the SPEC names it),
  so choosing option A means **`tools/gen_models.py` must carry a GPL
  header**, and the repo then contains GPL code alongside MIT-vendored `three`.
  That is *legally fine* (GPL and MIT coexist; only the GPL file is
  copyleft-encumbered) but it is a real, permanent licensing asymmetry in a repo
  that is otherwise cleanly MIT + CC0-by-generation.
* Blender is also a ~400 MB dependency for what is fundamentally a
  box-and-cylinder problem.

### 5.3 Recommendation: **Option B — Python `trimesh` + `numpy`**

**Why B over A:**

1. **License hygiene.** `trimesh` is MIT and `numpy` is BSD-3. The generator
   stays permissively licensed and the repo has **one** licensing story instead
   of two. This is the single strongest argument.
2. **It fits the actual geometry.** Our ships are parametric capital-ship
   hulls — extruded profiles, tapered boxes, cylinders for engine bells and gun
   barrels, a wedge bow, a tower superstructure. `trimesh.creation` covers all of
   it (`box`, `cylinder`, `capsule`, `extrude_triangulation`, `sweep_polygon`),
   and `apply_transform` handles placement. We do not need subdivision surfaces
   or sculpting.
3. **One-call OBJ+MTL export.** `trimesh.exchange.obj.export_obj(mesh,
   mtl_name='yamato.mtl', include_normals=True, include_color=False,
   include_texture=False)` returns the OBJ text and the MTL payload — exactly the
   SPEC §5 artefact pair, with no Blender in the loop.
4. **CI-friendly.** `pip install trimesh numpy` in a GitHub Action and
   `tools/gen_models.py` runs headless in under a second. A Blender-based
   generator needs a Blender download and a `--background --python` invocation.
5. **`trimesh` is also the validator.** `tools/validate_models.py` can *load the
   generated OBJ back* with `trimesh.load(..., group_material=False,
   split_groups=True)` and assert triangle count, watertightness, bounding box,
   group names, and normal presence — using the same library that wrote it.
   Blender would need a second Blender run to validate.

**Caveats to plan for:**

* **Groups.** SPEC §5 requires `g <groupname>`. `trimesh`'s `export_obj` writes
  groups from **scene geometry names**, not from an arbitrary string, so the
  generator must build a `trimesh.Scene` with one named `Trimesh` per part
  group rather than concatenating everything into one mesh. This is the one
  implementation detail asset-forge must get right on day one — build the ship
  as a `Scene` of named parts, then export.
* **Materials.** MTL `newmtl` names must come from the frozen 12-name palette.
  `trimesh` writes material names from the visual's material name, so set
  `mesh.visual = trimesh.visual.TextureVisuals(material=SimpleMaterial(name=...))`
  per group. Alternatively hand-write the MTL — it is ~15 lines and fully under
  our control, which is the lower-risk option.
* **Booleans.** `trimesh.boolean` needs the `manifold3d` soft-dependency. Prefer
  composing from primitives over boolean subtraction so the generator has no
  soft-dep at all; if a boolean is genuinely needed, add `manifold3d` to the
  tool requirements.
* **No textures.** Keep `include_texture=False` — SPEC §5 rule 1 forbids them.

**Option D stays in the toolkit** for radar/reticle/explosion sprites (§3.3),
and **option C is rejected** only because SPEC §5 mandates an OBJ/MTL artefact
and a Python-generated manifest.

## 6. Fan-work legal caution

*Space Battleship Yamato* (宇宙戦艦ヤマト) is a copyrighted and trademarked
franchise owned by **Voyager Holdings / YAMATO 2199 production committee** and
its licensors. This project is an **original tribute**, not a derivative work
that reuses any protected expression. That distinction is the whole legal
strategy, and it only holds if we keep it.

### 6.1 What we do

| We do | Why it is defensible |
|---|---|
| Build **original geometry** from parametric primitives | No protected expression is reproduced; only *ideas* (a battleship with a bow gun) which copyright does not protect |
| Use **original names in a fan context** and credit the inspiration in the README | Clear, honest labelling; the title says "inspired by" |
| Copy **numbers** (333 m length, 48 cm guns, 8 s charge) | Facts and measurements are not copyrightable |
| Synthesise **all audio** | No sound recording or composition is reproduced |
| Reimplement **mechanics** (shields, a charging superweapon) | Game mechanics are not copyrightable; only their expression is |

### 6.2 What we must never do

| Never | Why |
|---|---|
| Ship a **ripped model** from the anime, a game, or a mod | Straightforward infringement; also breaches R1 |
| **Rotoscope / trace** a screenshot into geometry | A traced copy is still a copy |
| Ship **show audio** (the theme, the wave motion gun SFX, voice lines) | Sound recordings and compositions are separately protected; this is the most common fan-project takedown trigger |
| Use **official logos, insignia, or the Japanese title lockup** | Trademark, not copyright — CC0 does not help, and fair use is weakest on logos |
| Market it as **official** or imply endorsement | False endorsement; also breaches the CC-BY "no endorsement" rule if we ever add CC-BY art |
| Sell it, or run ads on it | Commercial use destroys the strongest fair-use/patience arguments |
| Use **character names/likenesses** in a way that suggests the official story | Keep it to ship names and mechanical homage |

### 6.3 Practical guardrails for this repo

1. **A `NOTICE` section in `README.md`** stating: unofficial fan work, not
   affiliated with or endorsed by the rights holders, no third-party or
   franchise assets included, all geometry generated and all audio synthesised.
2. **A provenance claim the verifier can check.** The verifier should be able to
   assert that `assets/` contains *only* files whose names appear in
   `manifest.json` and that all of them were written by `tools/gen_models.py`.
   That is a concrete, testable form of R1 — recommend it as a test.
3. **No binary blobs in git history.** Once a ripped asset is committed it is
   in the history forever, even after deletion. This is why R1 is a *rule* and
   not a *review step*.
4. **Respond to takedowns.** If a rights holder objects, the correct response is
   to comply immediately. A demo is not worth a fight.

### 6.4 The honest bottom line

"Original tribute" reduces risk substantially but does not eliminate it —
trademark and character-design claims can still be brought, and no disclaimer
prevents a lawsuit, only weakens one. The realistic posture for a
non-commercial, clearly-labelled, asset-free fan demo is **low risk, not zero
risk**. Rules R1 and R5 are what keep it low; every exception raises it.
